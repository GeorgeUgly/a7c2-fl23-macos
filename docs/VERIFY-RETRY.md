# 取电池后，一直验证不过怎么办

**先不要恢复或重新安装，也不要删除原来的文件夹。** 验证失败不等于相机没装好。若安装已完成、上次验证仅看到本版本已知的旧运行内容，可以检查记录后重新验证。

0.2.2 补上了旧版 FL2 / FL3 的这类处理，同时保留新版两种版本的支持。它只允许检查，不会重新写入相机、恢复原版或补做安装。此兼容修正仅通过离线测试，尚未在报告问题的机身上验证。

[Issue #6](https://github.com/MDHan/a7c2-fl23-macos/issues/6) 是这次修正的具体兼容案例：旧版默认FL23、安装完成、6处磁盘均匹配目标，4处内存匹配目标，2处菜单标志内存匹配原版，`image_mode=0`，退出正常。运行时间可作为线索，不能仅据此认定使用者没有取电池，也不能保证再次验证必然通过。

## 请本地 AI 帮忙

先更新电脑上的工具并保留原备份。可把下面这段和原安装文件夹的位置交给本地 AI：

```text
我之前安装了 FL2/FL3，验证没通过；后来取过电池，但原记录一直不让继续。
请使用 a7c2-fl23-macos 0.2.2 或更新版本，先阅读 docs/VERIFY-RETRY.md。
保留原来的安装文件夹，先在电脑上检查上一次失败记录，不操作相机。
只有确认属于安装已完成、上次检查时仅看到本版本已知旧内容的验证失败，才确认我实际取电池重启，
然后只重新运行 verify。不要恢复、重新安装、删记录或手动修改状态。
我了解验证会连接相机并运行检查，授权在符合条件和真实重启后执行验证。
若不符合条件，请说明具体原因并停下；通过后再决定是否正常升级。
```

普通用户不用修改 `state.json`。如果 AI 只因看见 `needs_review` 就拒绝一切检查，请让它按本页完成离线审查；**这不是直接允许升级或重装**。

## 给协助操作的 AI

### 1. 更新并查看记录

在工具仓库中更新到0.2.2及以后版本，再运行 `./setup.sh` 和 `./a7c2-mac --version`。保留本地修改；更新发生冲突时先处理，不强行覆盖。设置 `A7C2_WORKSPACE` 为用户原来的安装目录，不创建新目录代替。

```sh
A7C2_WORKSPACE="$HOME/Pictures/A7C2-work"
./a7c2-mac status --workspace "$A7C2_WORKSPACE"
```

确认这个路径来自用户，不猜测电量、连接状态或是否已取电池。

### 2. 先完成离线审查

以下仅读取本地文件，不需要sudo、不连接USB、不更改原状态：

```sh
.venv/bin/python -B - "$A7C2_WORKSPACE" <<'PY'
import sys
from macfl23.workflow import MacJob

job = MacJob(sys.argv[1])
job.validate_candidates()
job.review_failed_verify_before_cold_start()
print('历史检查通过；保留原记录。真正取电池重启并重新连接后，可只重做验证。')
PY
```

必须成功完成这一步才安排取电池和设备验证。检查失败时保留输出，先分析，不手改阶段、不跳过校验。

### 3. 真正取电池后，只重做验证

离线审查通过、相机无异常后，请使用者正常关机、等存取灯灭、取电池约10秒再装回开机，重新连接USB并选择第2项影像传输（MSC）。等待使用者真实完成的确认；如果使用者已经实际完成，也应取得确认，不能仅凭命令选项推断。

```sh
sudo ./a7c2-mac verify --workspace "$A7C2_WORKSPACE" --cold-start-confirmed
```

这一步仍会完整检查相机程序、目标设置和实际运行内容。只有全部通过并正常返回USB，才记为 `verified_after_cold_start`；之后才按正常升级说明创建独立升级目录。原始失败证据保留。若是明确的USB返回未确认结果，仍按[状态说明](STATE-MACHINE.md)处理，不当作正常升级来源。

## 工具保留的限制

- 支持没有 `features` 的旧版 FL23目录、显式 `["fl23"]` 的旧目录，以及新版两类目录；不扩大到旧版NTSC实验组合。
- 原动作必须是 `verify`，原阶段为安装已完成、等待冷启动（包括已完成主体的USB返回未确认变体），错误须精确匹配对应版本的旧运行内容报错。
- 历史完整程序读回、唯一runtime原始报告、审计记录及正常MSC返回必须吻合；磁盘区域为目标，内存仅可为本版本已知的原始或目标内容且至少有一处旧内容。运行时间和image_mode可作线索，不据此认定用户没取电池，也不把它们变成额外的只读重验门槛。
- 有未知程序内容、参数错误、通信或清理结果不明、缺失/重复报告、安装中断或其他写入失败时，仍拒绝重验。`install`、`restore` 和 `upgrade` 不接受 `needs_review`。
- 再次验证失败会保留原失败阶段，并记录最新真实错误；只有真实通过后清除当前失败标识。对于旧工具已将阶段覆盖为 `needs_review` 的情况，必须有此前受控重验的有效审查记录，且本次历史报告也完整符合要求，才能只重验；没有证据不放行。

请先分享 `status` 输出及最早的具体报错，遮去个人路径；不要公开上传原始程序、备份、机身身份、完整状态或私人日志。
