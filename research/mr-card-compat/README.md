# FL2/FL3 存储卡预设：两字节离线候选补丁

**状态：已通过离线原生参数校验回归，尚未实机验证。** 这是供审查的候选补丁，不是已经验证可安装的修复版。没有修改默认安装流程，也没有相机写入命令。

针对的反馈：FL2/FL3 存入机身 1/2/3 后可调出，存入存储卡 M1–M4 后调出显示“文件错误”。[Sony A7C II 官方说明](https://helpguide.sony.net/ilc/2360/v1/en/contents/0413_setting_memory.html)确认 M1–M4 位于存储卡。

## 已找到的具体缺口

当前使用的 FL2/FL3 补丁已经允许主外观编号 17/18，并为它们设置外观绑定 10/11。但原版 AP 的另一张绑定能力表仍为：

```text
appFw.so 文件偏移与虚拟地址 0x4b2dcf8：
编号 0..9  = 01（允许）
编号 10/11 = 00（拒绝）
```

卡上预设的检查路径可以追踪为：

```text
check_ext_mr 0x2f55e20
  -> read_ext_mr 0x2f559d0（只检查分支）
  -> 0x2e2e380
  -> 完整参数校验 0x2e2232c
  -> 参数分派 0x28bbcc8
  -> 能力表检查 0x28bbad4
```

完整校验会检查普通/照片/视频三组外观绑定，每组 18 项。它们使用同一张 12 项能力表；分派表中引用它的恰好是参数 ID `0x14e9..0x151e` 共 54 项。将任何一项改为 10 或 11，都能在固件原有完整校验函数中得到拒绝结果。

**这确认了一个真实的校验缺口，与反馈现象相符；尚不能证明它是该用户文件报错的唯一原因。** 原生函数会检查全部绑定，所以还不能据此断言问题只取决于当前选择的外观；“其他外观正常”仍需对照实际存档内容和保存时机。当前没有取得报错的 CAMPR 文件，也未执行完整的文件保存/读取过程。

## 最小改动

```text
appFw.so @ 0x4b2dd02：00 00 -> 01 01
```

只开放已经由 FL2/FL3 移植使用的两个编号。CP 程序、成像曲线、文件结构、参数校验指令及其他能力表保持原字节。原生检查仍拒绝绑定编号 12 及以上、负值，以及不合法的其他字段。

候选支持两个精确输入，均须为现有项目固定版本；不接受原版、其他改装版本或已经应用本候选的程序。完整输入/输出 SHA-256 固定在 [patch_profile.py](patch_profile.py)，反向操作也核验完整指纹。它是本 Mac 适配项目的独立研究补丁；原 FL2/FL3 移植贡献归 [QAQLeonard](https://github.com/QAQLeonard/a7c2-fl23-research) 及其引用的研究作者。

## 离线构建

在独立的研究 Python 环境安装 [requirements.txt](requirements.txt)，随后从仓库根目录运行：

```sh
python research/mr-card-compat/build_and_verify.py \
  --source /path/to/existing/candidate/appFw.so \
  --output /path/to/new-private-output
```

不加 `sudo`。输入文件仅被读取；输出目录必须尚不存在，文件权限为 0600。依次完成完整指纹检查、两字节修改、反向还原核验、原生校验回归后，才生成：

- `appFw-mr-card.EXPERIMENTAL.so`：完整候选，仅保留本地。
- `verification.json`：指纹和验证摘要，不记录输入路径或机身信息。
- `full-model-cases.json`：生成的模型数据在原生校验函数中的前后结果。

脚本仅依赖普通文件和 Unicorn 模拟器，没有导入 USB 或相机接口。新研究模块没有接入生产 CLI；未知功能组合仍会被原流程拒绝。**不能把候选替换进已有安装目录、改状态文件，或使用原安装器重装来升级。** 真实升级还需要独立核验完整程序、运行内存、启动快照和既有工作目录的兼容性。

## 已验证的范围

默认 FL2/FL3 和附带 NTSC 提示选项的两个输入均分别验证，结果见 [verification.json](verification.json)：

- 每个输入执行 14,040 组原生分派检查的前后比较，覆盖全部 54 项绑定、0..256 及有符号边界值；仅 108 项判定变化，即 54 项各允许 10/11。
- 每个输入执行 216 组完整模型校验回归，覆盖三组绑定的所有 18 个槽及 10、11、12、`0xffffffff`。每份模型经过 2,018 次原生参数检查。
- FL2/FL3 主选择与三组绑定共同出现时，原检查拒绝、候选通过；不合法的主外观编号仍被拒绝。
- 输入原文件逐字节保留；完整候选反向还原与原输入完全相同。
- 60 项主机测试和 8 项固定版本上游离线测试通过。

测试输入是按原生约束生成的模型数据，不来自机身。只有错误列表记录器和诊断日志函数被显式替代；参数分派、表数据及判断指令均运行原生代码。

### 进一步复核

复核没有改变两个字节的补丁，也没有改变两个完整候选的 SHA-256。额外通过：

- ELF 段映射与重定位表独立交叉检查：改动位于 `.rodata`；这张表的 54 个重定位引用与 54 项绑定参数逐一对应。
- 模拟器把指令区及能力表设为只读；原生校验的写入限制在栈内，逐次检查栈指针和全部被调用者保存寄存器恢复。
- 10 组完整模型测试同时改变所有绑定，让每个槽覆盖原有 0..9；校验通过且模型输入保持原样。
- 全部 54 项绑定同时含 10/11 时，候选通过；再加入一项无关非法字段，候选仍拒绝。
- 16 组真实程序指纹负向检查：原版、重复应用、反向误用、截断、追加字节，以及窗口内/外篡改均被拒绝。
- 工具回归覆盖输出文件/符号链接保护、未知来源不产生候选，以及禁止 `-O` 关闭验证断言。

复核发现，直接运行上游测试会在固定源码目录产生 Python 缓存，随后被正常的清单保护拒绝。此次仅将本次测试生成的 3 个缓存文件移出，原源码未改；以后使用 `-B` 避免重现，未放宽文件清单保护。回归后 `./a7c2-mac check` 通过。

```sh
python -B -m unittest discover -s tests -v
python -B -m unittest discover -s .upstream/a7c2_fl23_preview/tests -v
./a7c2-mac check
```
