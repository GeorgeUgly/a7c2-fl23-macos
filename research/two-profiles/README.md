# 两类版本：共同的 M1–M4 修复，可选目标 NTSC 提示跳过

**离线验证通过，尚无这两类新版本的实机安装、升级、恢复或拍摄结果。** 本目录记录0.2.0的实现和证据，旧研究报告保持原样作为历史记录。

## 固定范围

| 用户选择 | 新建目录 features | 原版安装/恢复窗口 | 旧 FL2/FL3 升级窗口 | 运行核验区域 |
| --- | --- | --- | --- | --- |
| FL2/FL3 | `fl23, mr_card_compat` | 41 | 1 | 7 |
| FL2/FL3＋跳过 NTSC 提示 | 上述两项＋`no_ntsc_notice_v2` | 43 | 3 | 9 |

两类共享同一 FL2/FL3 移植和 CP 目标程序；M1–M4 能力表修复都在 AP `0x4b2dd02: 0000 -> 0101`。完整代码指纹对同型号、同固件版本通用，与序列号无关；保存设置和备份仍逐机保留，身份匹配不取消。

默认 AP SHA-256：`22137afdb226ed2a5c0804eb95e802f4d697955fa793c7661e6b14bd48127d89`。

带跳过提示 AP SHA-256：`c8cc89e73e0bd03c91e5a9c7147c2d8c829cfea6b8dbd6fd2be20a4eacf423db`。

共同 CP SHA-256：`60a9de1a0636c7f6b5b98607a4d25eeb48634e25294f632743a6d256e583b370`。

## NTSC 补丁收窄

旧补丁在制式比较处跳过整段条件，扩展模拟发现其影响非 NTSC 消息的选择。新版本恢复这些比较原字节，只在已经选中目标消息的两处修改一条指令：

| 文件偏移/VA | 原字节 | 新字节 | 行为 |
| --- | --- | --- | --- |
| `0x2061880` | `626d8052` | `07000014` | `mov w2,#0x36b` 改为跳到 `0x206189c` 正常后续入口 |
| `0x2061da8` | `626d8052` | `0a000014` | 同一目标消息改为跳到 `0x2061dd0` |

进入这两个位置前，原程序已经执行地区、制式不一致、重置/启动类型及显示条件判断。新指令不改通用寄存器和 NZCV。PAL 消息、无显示时选择其他消息的路径都保留原代码。不同于把消息 ID 换为空值，此处进入原有正常后续分支。

24,576 组原生窗口模拟覆盖两个后段模式、地区0/1、两个入口、当前/默认制式0/1、重置0/1、启动类型0..3、显示0/1及显式外部谓词组合。576 组目标 NTSC 消息改走正常后续，结果与原程序不启用该地区条件的参考消息一致；其余24,000组的消息、指令路径和通用寄存器完全一致。未证明全部组合的整机可达性，没有执行完整启动或渲染。

## 构建、安装、升级和恢复

固定上游及默认的旧模块不改动，旧工作目录仍按原 features 验证和恢复。两类新版本都使用独立的 installer、upgrade、runtime 小型工作器和清单；它们不是 Sony 完整固件。源码和移植归属见[完整致谢](../../ACKNOWLEDGEMENTS.md)。

新机从精确原版2.01备份准备，两种选择分别派发41/43窗口安装器。已安装旧 FL2/FL3 的机身经[独立升级流程](../../docs/UPGRADE.md)重建新目录；升级只修改1/3个 AP 窗口，不改 CP 程序、不写或保存拍摄设置。源目录保持不变。当前不支持旧 NTSC 组合和其他改装的直接升级。

两类都支持反向恢复为自己的原版程序及原始目标设置，并补充恢复后的冷启动 verify。写入前后完整指纹、窗口读回、只读挂载恢复和失败时反向回退的约束沿用固定上游；不绕过未知字段，不允许无证据重跑或手改状态。实际救援能力和恢复成功仍待实机验证。

六个 AArch64 模块分别重复构建两次，输出一致；逐项反查41/43窗口和1/3窗口的编译后元数据及前后字节，运行读取器覆盖7/9区域；无动态库依赖、未解析符号或非预期重定位。单窗口升级表显式保留，避免优化后失去可核验元数据。

固定安装器 C 源码另经过24项本机测试：两类版本各自的完整安装器和追加升级器，分别检查只校验、安装、反向恢复、错误完整指纹、inode变化及部分写入失败后的回退。仅替换系统调用入口及测试入口名称；实际执行原有完整文件 SHA-256 和安装状态机。系统调用/文件系统使用明确替代，不是 AArch64/Linux内核/ext2或相机测试。

## 离线复现

先完成普通项目 setup。研究环境使用 Python3.10+，安装 [MR研究依赖](../mr-card-compat/requirements.txt)。以自己的原始备份目录为输入；输出必须放在仓库外、不存在的私有目录。以下不加 sudo，不连接相机：

```sh
python -B research/two-profiles/verify_offline.py \
  --workspace /path/to/existing-work \
  --output /path/to/new-private-regression
python -B tools/test_integrated_native.py \
  --workspace /path/to/existing-work \
  --output /path/to/new-private-native-tests
```

本机 C 测试还需要可用的 `cc` 编译器。固定 Zig0.13.0 构建新模块：

```sh
python -B tools/build_integrated_native.py --zig /path/to/zig
```

公开结果见 [verification.json](verification.json) 和 [native-installer-tests.json](native-installer-tests.json)。主机自动测试和固定上游测试另按主README/CI执行。公开文件不包括完整固件、机身备份、保存设置、身份、原始日志或个人路径。

实际报错 CAMPR 文件、文件头/校验和/序列化和存储卡文件系统未执行；真实 M1–M4 保存/调出、机身1/2/3、完整启动/视频、拍摄像素、安装/升级/WBI/恢复及冷启动尚未验证。首次安装的已知 `writing_settings` 问题不因新增版本而被视为解决；新版也不套用旧版专项 diagnose/finish-install。以上通过项只定义离线证据范围。
